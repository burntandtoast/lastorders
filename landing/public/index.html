What happens if you do nothing

On the shutdown date the retired model stops working. OpenAI's own wording: at shut down, “the model or endpoint will no longer be accessible.” Anthropic's: “Requests to retired models will fail.” Anything still calling those IDs — a chatbot, a summariser, a classifier, a background automation — starts getting errors that day. In a queue or cron job that can look like silence until someone notices the backlog.

The feature stops responding

Requests to the retired model ID fail. Chat UIs go blank, summaries never arrive, classifiers never return a label. Background jobs often fail quietly until something downstream breaks.

Fine-tunes go with the base model

Fine-tuned models built on those bases are switched off on the same day, and gpt-6-luna can't be fine-tuned, so you can't recreate them there. New fine-tuning jobs stop on 6 January 2027.

A hurried name-only swap breaks too

Changing only the model string is not enough. In our own API checks, gpt-6-luna rejects max_tokens, and Chat Completions tool calls fail unless reasoning_effort is set to none.

Why it isn't just find-and-replace

Swapping the model name looks like a five-minute job. Usually it's mostly that, plus the bits that break quietly.

Tool calls can stop working

On Chat Completions, the January replacement gpt-6-luna only supports function calling when reasoning_effort is set to none. The default is medium. Change only the model string and your tool calls break. The fix is a code change, or a move to the Responses API.

max_tokens and sampling parameters break

gpt-6-luna rejects max_tokens outright. temperature, top_p and logprobs only work with reasoning_effort set to none. Nearly any production code breaks on a plain name swap. Use max_completion_tokens (or max_output_tokens on the Responses API) and set reasoning_effort where you still need those parameters.

Fine-tunes have no direct replacement

gpt-6-luna can't be fine-tuned. Your fine-tuned model is switched off with its base model on 14 January, and new fine-tuning jobs stop on 6 January. You need a plan before then, not a patch afterwards.

Outputs drift

A new model answers slightly differently. JSON fields get renamed, a classifier sorts things into different buckets, a summary runs longer. Nothing errors, but something downstream does the wrong thing.

Model IDs hide everywhere

Config files, environment variables, database seeds, test fixtures, settings migrations, docs your users copy. The ones you forget about turn up on shutdown day.

Undated aliases

gpt-4o or gpt-4.1-mini with no date still resolves to a snapshot on the list. Live check: gpt-4o currently points to gpt-4o-2024-08-06, which retires on 14 January 2027. And the API's shutdown_date field is still empty for that batch, so an empty date doesn't mean you're safe.

Questions

Is the scan really free? What's the catch?

It's free, with no account and no card. It tells you what's affected and when. If that's a one-line fix, it says so, and you can make it yourself. You only pay if you want the automatic patch and the regression report, or want us to do the work.

Does my code leave my machine?

No. The scan and the licensed fix both run where your code already is, on your laptop or in your own CI. There's no telemetry, and your code and prompts never leave your machine. The only contact with us is to fetch the retirement list and check a licence key; pass --offline to use the bundled list instead. The regression report calls OpenAI with your own API key, so your prompts go to OpenAI as they do today and nowhere else.

Can't we just change the model name ourselves?

Often you can, and the scan will say so. The traps are tool calls on Chat Completions (which need reasoning_effort set to none on gpt-6-luna), max_tokens (which gpt-6-luna rejects outright), sampling parameters that only work with reasoning_effort: "none", fine-tunes, and quiet output drift. The report exists so you can see whether any of those apply to you.

Can I change the settings first and switch models later?

No. GPT-4o and GPT-4.1 reject reasoning_effort, and gpt-6-luna needs it (and rejects max_tokens), so the settings changes and the model switch must ship together in one change; Last Orders enforces this. Found in our own API checks.

We use a fine-tuned GPT-4o or GPT-4.1 model. What happens?

Fine-tuned models follow their base model's schedule, so they're switched off on 14 January 2027. gpt-6-luna can't be fine-tuned, and new fine-tuning jobs stop on 6 January 2027. The scan will list your fine-tunes, but the licence won't patch them, because there's nothing to patch them to. That's what the fine-tune tier (from £3,500) is for. Get in touch early, because some routes need that 6 January date.

We're on gpt-4.1-nano or gpt-4o-2024-05-13.

Those go on 23 October 2026, which is days away. Run the scan today. OpenAI recommends gpt-5.6-luna and gpt-5.6-sol as their replacements. If you'd rather we did it, email us and we'll move you up the queue.

OpenAI's API shows no shutdown date for our model. Are we safe?

Not necessarily. The shutdown_date field on OpenAI's List models endpoint is still empty for the GPT-4o and 4.1 batch, even though those snapshots retire on 14 January 2027. Earlier retirements (such as gpt-4.1-nano and gpt-4o-2024-05-13) do show a date. Last Orders works from OpenAI's deprecations page, not just that field.

What won't the scan find?

Model IDs built at runtime (say "gpt-" + version) or stored only in a database. It does list environment variables that choose the model, so you can check their live values. If you want certainty, check your OpenAI usage for calls to GPT-4o or 4.1 after you deploy.

What does "per repo" mean?

One licence covers one GitHub repository, monorepos included, and future retirements in that same repo. If you've got lots of repos, email us and we'll sort something sensible.

Does it cover Anthropic as well as OpenAI?
